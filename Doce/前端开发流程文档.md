### 2.2 初始化步骤及配置

1. 在 frontend 初始化 Vue 3 的 JavaScript Vite 项目；选择与所选 Vite 兼容的 Node LTS，并记录 Node/npm 版本与 engines。
2. 从官方来源核对并固定依赖版本，生成 package-lock.json。SheetJS 安装按官方分发说明选固定版本，不直接把未核对的 registry xlsx 或 latest URL 作为生产依赖。[SheetJS 安装说明](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)
3. 配置下列 scripts、路由、样式、API 地址及代理；引入 Element Plus 中文语言包。锁文件生成后用 npm ci 验证可重复安装。
4. 只为浏览器开放应用路径与 API 路径；模型密钥、数据库、JWT 签名密钥和加密主密钥全部留在后端。VITE_ 变量会进入客户端构建产物。[Vite 环境变量说明](https://vite.dev/guide/env-and-mode)

拟定 scripts：

~~~json
{
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5173 --strictPort",
    "build": "vite build",
    "preview": "vite preview --host 127.0.0.1 --port 4173 --strictPort",
    "lint": "eslint .",
    "test": "vitest run",
    "test:e2e": "playwright test"
  }
}
~~~

对应安装并锁定 ESLint、Vue ESLint 插件、Vitest、Playwright 和必要配置后这些 scripts 才可使用；本次没有初始化或执行。Vue 测试直接针对组合函数、适配器及浏览器行为，不为每个静态文字卡片新增镜像测试。[Vitest 官方说明](https://vitest.dev/guide/)

拟定 frontend/.env.example：

~~~dotenv
VITE_API_BASE=/api
VITE_APP_BASE=/
API_PROXY_TARGET=http://127.0.0.1:8000
~~~

API_PROXY_TARGET 只供开发代理读取，不含凭据。API 基路径已含 /api；API 模块路径只写 /products 等，文件 file_url 已含 /api 时不再重复拼接。

拟定 vite.config.js：

~~~javascript
import { defineConfig, loadEnv } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  return {
    plugins: [vue()],
    base: env.VITE_APP_BASE || '/',
    server: {
      host: '127.0.0.1',
      port: 5173,
      strictPort: true,
      proxy: {
        '/api': {
          target: env.API_PROXY_TARGET || 'http://127.0.0.1:8000',
          changeOrigin: true
        }
      }
    },
    build: { sourcemap: false }
  }
})
~~~

代理保留 /api 前缀，后端及文件共用该入口。生产请求使用同源 /api；不能认为 Vite 的 server.proxy 会随 dist 部署生效。[Vite 开发代理](https://vite.dev/config/server-options)、[构建与路径说明](https://vite.dev/guide/build)

### 2.3 联调前必须固定的 Schema

以实际 /openapi.json 及经过脱敏的响应样例检查后端需求 §3—§6，记录版本日期。以下是 F0 检查门槛，缺项须由后端落实，不用假字段或另一个新 API 替代。

| 检查 | 必须满足 |
| --- | --- |
| JSON、状态码 | 成功直接资源或分页体；创建 201、素材任务 202；错误 code/message/details，details 含 field/row_number/reason。不套自造 data 层。 |
| 分页 | 普通资源列表 items/total/page/page_size；导入批次的 rows 内含相同分页体。每日数据汇总覆盖全部筛选记录，不随当前页缩小。 |
| 版本 | expected_version 校验；内容、建议、报告 PATCH 返回新 id/version。归属、引用和原快照可读取。 |
| 恢复索引 | rounds 各项的 resource_index 可找到内容、建议、实验和报告；建议有 proposal_key/is_current/content_confirmed。 |
| 任务 | 列表与详情有 terminal/retry_available/poll_interval_seconds/attempts/config_snapshot/original_task_id/material_id，以及取消及排队时间。 |
| 字段单位 | 金额十进制字符串；计数整数；百分比 API 为小数；业务日期 YYYY-MM-DD，操作时间带时区。 |
| 部分落库错误 | close-period 失败可 GET 实验看到保存范围；next-round 错误 details 指出已保存 round_id，轮次索引能查到来源和所选行动。 |
| 文件及导入 | file_url 鉴权；Content-Type 正确；sheet_name 与原表头→规范字段映射一致；全批明细可分页取得。 |

对 dashboard、shops、trend、预警、每日汇总等嵌套输出，由后端按需求落实对应字段，再由明确的页面适配函数读取。不要通过多层“可能叫这个名字”的容错代码掩盖字段未确定。字段不一致记录具体响应、期望和对应后端步骤，先修正契约再继续该能力联调。

## 3. F1：会话、页面壳与主管配置

### 3.1 登录与路由

| 页面路由 | 行为 | 角色 |
| --- | --- | --- |
| /login | 必填校验→POST /auth/login→保存 token→GET /auth/me→进入有效站内来源地址或大盘 | 未登录 |
| /dashboard | 大盘和店铺概览；根路径跳转至此 | O/M |
| /workbench/:productId | 三分区工作台，query 使用 roundId、tab，可带 shopId/experimentId 及选中版本 ID | O/M |
| /imports | 类型、映射、预览、结果；可用 batchId query 恢复已有批次 | O/M，M 只读 |
| /settings | 模型、队列、模拟授权 | M |
| 未知路径 | 未找到页面与返回入口 | 不新增业务导航 |

`tab` 仅接受 diagnosis/creative/review；后端 phase 不与 tab 混用。工作台侧栏入口复用商品选择对话框，有商品后再进入对应路径，不增设一个管理页面。

会话实现：

- token 保存到 sessionStorage；普通用户信息存在内存，刷新首先 GET /auth/me，并在鉴权完成前阻止业务组件加载。
- ensureSession 复用同一个初始化 Promise，避免守卫和组件各发一次 me。角色只认 me 当前响应，不信任存储中的旧 role。
- 登录来源只允许本应用的合法路由及参数，拒绝外站地址。manager 仍不可编辑运营内容。
- 401 只触发一次会话失效处理，停止轮询、取消视图 GET、清除 token，进入登录；不重放原写请求。403 保持登录，显示无权限。
- 过期时仅可暂留普通编辑草稿在内存；重登同一用户且同上下文才可询问恢复。密码、配置密钥不暂存。退出或换用户清空草稿、查询缓存、定时器和对象 URL。
- beforeEach 做身份与路由角色控制，页面按钮再按 permissions.js 控制，后端仍验证每次请求。

角色矩阵完全沿用前端需求 §2.3；主管只拥有审批和配置写权限，运营无配置读取权限。业务只读页仍能查看版本、素材、实验及报告。

### 3.2 HTTP 层必须具备的行为

| 场景 | 实施 |
| --- | --- |
| JSON | 当前 token 放 Authorization；业务字段显式白名单构造；返回原资源，不默默 unwrap data。 |
| multipart | 使用 FormData，将 field_mapping JSON.stringify；不手写 Content-Type，让浏览器生成 boundary。选择文件不自动提交 import。 |
| 文件 | 授权 fetch 后检查 HTTP、MIME 类型，再取 Blob；错误体即使下载接口也按 JSON 错误解析，不把它显示成文件。 |
| API 地址 | 对后端返回的 file_url 校验为受信任 API 地址再附加 token；不向任意来源 URL 发送 Bearer。 |
| 失败 | Error 包含 status/code/message/details；网络或浏览器中止作为客户端错误分类，不能伪造为服务端 failed 或 422。 |
| 时间 | 普通读取允许取消。文字生成的浏览器等待不能低于后端服务超时；网关等待须覆盖服务调用和保存。中止 fetch 不等于取消后端操作。 |
| 重试 | 查询可由用户重试；写操作禁止自动重试。请求结果不明先 GET／索引确认。生成也可能已经保存新版本。 |
| 反馈 | 422 定位字段／行；409 保留输入并重新读当前版本；502/504 保留旧内容并按该业务恢复路径处理。 |
| 日志 | 只记录请求方法、脱敏路径、状态、时间及业务 code；不打印 token、密码、密钥、原导入文件或整段模型资料。 |

查询统一读 HTTP 状态和区域 QueryState；保存按钮用 finally 恢复 loading，仅成功后更新 baseline。失败不清空输入，不自动显示“保存成功”。确认、审批、导入、创建轮次等待期间禁用重复提交。

### 3.3 壳、视觉与响应式

AppLayout 使用约 204px 侧栏、约 66px 顶栏、主体内滚动，浅色背景和蓝色主操作沿用样张及 Element Plus。沿用 00 图的 8px 间距体系，常用 16/24px；正文 14px、辅助 12px、区域标题 18px、页面标题 26px。表单、状态与可点击操作用可读文字；组件尺寸、焦点和错误定位可实际操作。

顶栏用户与角色来自 me，日期动态展示；主管增加配置入口。返回大盘按钮在大盘本页省略。图中的铃铛、品牌字样、示例账号是视觉辅助，没有通知接口就不建设通知中心，铃铛省略或无交互装饰。

页面内容宽度流式，设计图 1440×1200 是全页参考，不能写成固定页面宽高。1366×768 时步骤横向滚动、表格容器滚动，主要按钮保持可达；1920×1080 时同一组件网格扩展；窄屏折叠侧栏、表单单列、预览与编辑纵向排列。弹窗最大高度限制在视口内，表单内容滚动，底部操作保持可见。

### 3.4 配置与后端 P1 对接

1. 主管 GET /settings/services、GET /settings/queue 和店铺列表，分别展示加载状态；配置读取失败的区块禁止保存空值覆盖。
2. 服务保存 PATCH /settings/services，只提交改变的 base_url/model/temperature/request_timeout_seconds/multimodal_mode；mode 为 simulation。
3. api_key_masked 只展示，另设更新输入。未更新则省略 api_key；成功、失效或离开后清空密钥输入并重新 GET 脱敏配置。失败保留普通字段，密钥由用户重新输入。
4. 队列 PATCH 提交改变的 concurrency/execution_timeout_seconds/max_auto_retries/poll_interval_seconds；调度和心跳参数可放展开的高级字段，默认仍是已有规则，heartbeat 小于期限。
5. 模拟授权 PATCH /settings/shops/{id}/authorization，状态仅 not_configured/authorized/expired；店铺平台及接入标识由基础档案提供，不在授权接口重复编辑。
6. 解释 2 秒、2 并发、60 秒、2 次额外重试；并发用当前规则，期限／重试使用任务快照。不提供不存在的“连接测试”接口，文字服务通过真实业务生成验证。

完成证据：O/M 登录、刷新 me、运营配置 403、主管业务写入 403、脱敏配置 GET/PATCH、修改人时间；初始没有店铺时先由运营建店，再主管配置授权。

## 4. F2：工作台恢复、编辑与请求竞态

### 4.1 恢复顺序

1. 校验 productId、query roundId/tab，GET /products/{id}；无资源显示 404，不用其他商品填充。
2. GET /products/{id}/rounds 分页获取可选轮次。无指定轮次选最新；无轮次只提示运营显式 POST 首轮。主管访问不自动创建。
3. 校验指定轮次确属该商品，读 resource_index。用索引 ID 请求当前标签必需详情，其余标签进入时加载；任务和素材按 product_id/round_id 查询。
4. 同 proposal_key 选 is_current 版本；主管待审仅用 current、pending_approval、未归档项。批准旧版及旧实验保留在历史入口。
5. 实验从索引选择并 GET /experiments/{id}，其 groups、reviews、周期和目标用于经营与报告；只通过所选实验确定店铺范围。
6. 历史详情使用原版及引用快照，不用当前商品售价、当前创意或新版素材替换当时记录。

选中店铺／实验或打开历史版本时同步非敏感 query：shopId、experimentId、contentId、proposalId、reviewId（仅保留当前视图适用项）。刷新按索引验证其商品、轮次、店铺和类型后恢复；非法或越权 ID 显示错误，不能静默串入别的资源。默认选择后 replace 规范地址，用户显式切换再 push；复制链接、前进后退也经过未保存保护。URL 不放 token、密钥、业务正文或文件原始路径。

`phase`：setup→diagnosis→creative→material→ad→data→review 由后端最高进展推导；“下一轮”是行动入口，不另造 phase。步骤可以浏览历史，写按钮单独看所选版本、实验和店铺的前置条件，不能因 phase=data 就认为任何店铺实验都已批准。

### 4.2 唯一上下文与切换

useWorkbenchContext 提供 productId/roundId/tab/selectedShopId/selectedExperimentId 和 requestEpoch。商品／轮次改变先经过未保存保护，再停止旧轮询、取消视图 GET、释放预览 URL、清空旧区数据、增加 epoch、读取新索引。

店铺切换只更新上架、库存、建议、实验和经营范围，统一商品／轮次及符合归属的内容素材保留。切换实验清空原日期、组别及报表缓存，重新按实验周期加载。筛选提交使页码回 1；总数以后端分页体为准，不能用当前 items.length 当 total。

GET 防竞态核心参考；AbortController 用于取消浏览器读取，epoch 用于拒绝已返回的旧响应。[MDN AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)

~~~javascript
let querySequence = 0
let readController

async function refreshPanel(contextKey, params) {
  const sequence = ++querySequence
  readController?.abort()
  readController = new AbortController()
  setQueryState('loading')
  try {
    const result = await loadPanel(params, readController.signal)
    if (sequence !== querySequence || contextKey !== currentContextKey()) return
    setPanelData(result)
    setQueryState('ready')
  } catch (error) {
    if (sequence !== querySequence || contextKey !== currentContextKey()) return
    if (error.name !== 'AbortError') setQueryError(error)
  }
}
~~~

每个区自己的请求序号与 signal，不共享一个让其它区相互取消的 controller。响应体再核对商品／轮次／实验归属；写请求返回时若已离开原上下文，只刷新所属资源索引，不把返回值塞到当前商品。刷新、路由 watch、图表初始化都只读取，不能发 POST。

Vue Router 同组件参数更新须使用 onBeforeRouteUpdate 或对应守卫保护编辑，再监听具体参数；不只使用 onBeforeRouteLeave，也不 watch 整个 route 触发全页反复加载。[Vue Router 组合式 API](https://router.vuejs.org/guide/advanced/composition-api.html)

### 4.3 编辑与版本保存

useDirtyForm 持有服务端 baseline、表单 draft、dirty、saving、字段错误。校验用于及时反馈，服务端校验最终决定。深拷贝结构内容再编辑，不能直接改查询响应对象让历史也变。

- 内部切换／关闭提供“保存后离开／放弃修改／继续编辑”；保存失败留在原区。dirty 时注册 beforeunload，保存或卸载后移除。
- 保存与确认分开；界面提供“保存并预览”时只执行保存和本地预览，不自动 confirm。
- 内容／建议／报告 PATCH 提交 expected_version，成功返回新 id/version，替换当前选择并刷新索引；后续 confirm/submit/生成都使用新 ID。
- 409 保留本地草稿，展示最新版本对比；由用户决定重新核对后保存，不自动带新 expected_version 覆盖。
- 归档可操作允许的目标历史版本；编辑及审批只能用当前合法版本。归档退出新选择，历史入口和引用保留。
- 会话、配置密钥与文件清理按 F1；表单退出与标签切换共用同一个保护入口，避免反复弹两个确认框。

公共 QueryState 区分首次加载、无数据、无权限、读失败与提交失败；查询失败保留最后更新时间和旧值并注明未更新，不能显示为零。状态提示均有文字，按钮禁用必须说明原因。

### 5.2 竞品及核对

GET /products/{id}/competitors 支持分页与 verification_status。手工 POST 的资料及导入都先 unverified；展示出处 URL 与来源说明，教学资料明确标识。

关键资料修改后显示需重新核对，确认状态读取后端。对比表以本商品规格/价格和 verified 竞品为依据；不会自动改售价，来源链接不触发网页抓取。

### 5.3 大盘及统计接入

GET /dashboard 使用 shop_id/date_from/date_to；GET /products 使用 keyword/shop_id/page/page_size；店铺列表独立 GET /shops。默认当天及前六个业务日，正式教学周期通过显式筛选选择。

区域加载分别控制：店铺卡片、汇总指标、趋势、库存预警、商品搜索表。显示商品去重数量、动销率、曝光/点击/订单/GMV/花费、CTR/转化率/ROI；趋势指标可切换，不同单位分开坐标，缺数据点保持缺口。

点击店铺应用筛选；预警入口进入商品、定位店铺 SKU 映射及流水。快速建档和四类导入仅运营；主管入口只读。新增档案、库存或经营回填后重新请求相关汇总和列表，不本地加减全局数字。

### 6.2 Quill 与结构字段的保存约定

RichTextField 按结构字段编辑，主图四字段、视频钩子／画面／台词／促单分别绑定，工具栏支持现有样张的常用排版。selection_id 在该版本中稳定，不用数组位置作为跨版本业务标识。

content 中各业务字符串由该字段编辑器的文字值生成；edited_content 使用契约已允许的一个标准 Quill Delta 保存排版，不能用 HTML 代替结构字段。实现 creativeDelta.js 的序列化适配：

1. 按 content 的主图／脚本／镜头顺序列出稳定字段目录，每个目录项含 selection_id、字段路径、固定字段标题和文字。
2. 字段编辑器取得 Delta 与纯文本。保存时将固定标题和各字段 Delta 按该目录合并为一个完整 Delta，同时更新 content 的对应文字；其余未编辑字段原样保留。
3. 读取时根据同一版本 content 的目录、标题和文字长度定位 Delta 的各段，恢复对应字段样式；验证恢复段的纯文本与 content 一致。
4. 没有 edited_content 的模型草稿从 content 初始化普通文本；遇到旧排版与结构不匹配，明确提示并以结构内容恢复，不能猜测或丢弃业务字段。
5. 保存整个 content 和合并 Delta；不向 API 添加未定义的 field_deltas、HTML 或镜头时长字段。镜头编号、展示时间说明可作为本地视觉信息，业务 payload 只发已有字段。
6. 通过“多字段格式修改→保存→刷新→切换方向／脚本→再次保存”验证排版、文字、选择及未编辑项都保留；一并验证空字段和无效选择不能确认。

适配器只允许文本和已批准的常用样式，不支持任意 embed。固定标题／分隔符不进入可编辑字段；Quill 文本及 Delta 长度使用同一 UTF-16 索引和统一换行规则，只规范编辑器强制的末尾换行，不能 trim 掉用户有意的空格／空行。新增／删除镜头后重建目录并重组 Delta，不能按旧偏移切片；重载失败的格式须提示，业务文字始终来自结构字段。

允许使用 Quill 的 getContents/setContents 获取和恢复 Delta；组件销毁解除事件监听，初始化加载不触发 dirty。预览富文本 HTML 时净化，并限制工具栏及外链，禁止脚本或任意嵌入内容。[Quill API](https://quilljs.com/docs/api)、[Delta 说明](https://quilljs.com/docs/delta)

历史诊断与创意只读。素材调整通过新创意版本和新任务实现；本版不提供覆盖图片或视频文件的编辑接口。

完成证据：五类诊断、三组差异主图、三套完整分镜、修改后刷新读取、新旧版本及确认记录；真实调用失败和结构不合格有具体反馈，不用静态文字伪装真实结果。

## 7. F5：异步任务与素材文件

### 7.1 入队、跟踪与终态

POST /tasks 输入 creative_content_id/selection_id/task_type，以及教学演示需要的 demo_scenario。scenario 取 success/fail_once/always_fail/timeout/late_result；取消仍调用 cancel，不把“取消”当一个客户端伪造制作结果。图 10 的教学路径选择对应这些后端值。

202 响应表示持久化 pending，不表示生成完成。GET /tasks 用 product_id/round_id/status/task_type/page/page_size，详情 GET /tasks/{id}。默认每 2 秒，之后读 poll_interval_seconds；运营不得为了取间隔读取 /settings/queue。

| 任务状态 | 展示与动作 |
| --- | --- |
| pending | 排队、queued_at 与等待耗时；可取消。 |
| running | 本次 started_at、运行耗时、deadline_at；可取消。 |
| succeeded | 生成成功，查看 material_id；待审核素材不自动可用。 |
| failed/timeout 且 terminal=false | 本次尝试失败／超时，自动重试中，继续轮询；不开放人工重试。 |
| failed/timeout 且 terminal=true | 最终失败／超时；retry_available=true 才可人工重试。 |
| cancelled | 取消时间、原因和原尝试记录；停止轮询，不可原地重开。 |

时间线按 attempt_number 展示 queued/start/finish、状态、期限、心跳及错误。展示 config_snapshot 与 original_task_id，说明首次之外最多再重试两次。前端耗时仅辅助展示，不自行把任务判 timeout，不把排队时间计入 execution_timeout_seconds。

列表一个串行查询循环，详情展开时跟踪需要的详情；不为每行创建独立 setInterval。当前页全部 terminal=true 时停止该视图跟踪；换页／重新进入立即 GET 持久化记录。不会因停止视图轮询而停止 worker。

轮询核心参考：

~~~javascript
function createTaskPolling(read, render, reportReadError, isSameContext) {
  let stopped = true
  let timer
  let controller
  let intervalMs = 2000
  let generation = 0

  async function tick(run) {
    if (stopped || run !== generation || !isSameContext()) return
    const requestController = new AbortController()
    controller = requestController
    let continuePolling = true
    try {
      const task = await read(requestController.signal)
      if (stopped || run !== generation || !isSameContext()) return
      if (!Number.isInteger(task.poll_interval_seconds) ||
          task.poll_interval_seconds <= 0) throw new Error('轮询契约缺失')
      intervalMs = task.poll_interval_seconds * 1000
      render(task)
      continuePolling = task.terminal !== true
    } catch (error) {
      if (stopped || run !== generation || !isSameContext()) return
      reportReadError(error)
      if (error.status === 401 || error.status === 403 ||
          error.status === 404) continuePolling = false
    } finally {
      if (!stopped && run === generation && isSameContext() && continuePolling) {
        timer = setTimeout(() => tick(run), intervalMs)
      }
    }
  }

  return {
    start() {
      if (!stopped) return
      stopped = false
      void tick(++generation)
    },
    stop() {
      stopped = true
      generation++
      clearTimeout(timer)
      controller?.abort()
    }
  }
}
~~~

read 请求结束才安排下一次，列表版将停止条件改为当前 items 都 terminal=true。读取超时由 HTTP 层结束请求，错误保留原任务状态并显示最后更新时间；可暂停／手动重新获取，网络恢复只重读。标签切换、上下文改变、401、退出及卸载调用 stop，timer 与旧回包均隔离。

取消前显示任务、版本和状态，POST /tasks/{id}/cancel。成功重读任务；409 可能已结束，刷新后展示真实结果。结果未知只 GET 该任务，不再次无条件 cancel。retry 返回新的 202 task，切到新任务同时保留原任务链接；旧任务不改成 pending。

### 7.2 素材选择、审核与历史

GET /materials 按当前 product_id/round_id/review_status/include_archived 查询。卡片显示类型、版本、来源创意和任务、is_demo、review_status、tags、archived_at；名称可由原创意选定项标题展示，API 的业务标识始终用素材 ID。

审核 POST /materials/{id}/review，decision=usable/rejected；驳回时提供业务意见。标签 PATCH /materials/{id}/tags；归档 POST /materials/{id}/archive。成功重新读列表／记录，并更新可用素材选择器；主管只有预览。归档确认说明退出新选择但保留历史文件、审批及实验引用。

素材类型、标签及名称搜索是已有界面功能，但当前契约只明确审核／归档等服务端筛选。为保持现有路径并避免“只筛当前页”：
- 在当前商品与轮次内，按稳定分页取齐符合服务端筛选的素材元数据；前端对 material_type、tags、素材 ID／创意标题作过滤，再对过滤结果分页，显示其实际总数。
- 不预取文件，只有可见缩略图或已打开预览才请求 Blob。切换条件或上下文后重建完整范围集合，返回失败显示未完成，不能以部分集合给出全量总数。
- 如果实施时后端增加同 GET 的等价筛选参数，先同步契约和覆盖测试，再切换为服务端筛选；不在当前文档假定已有 keyword/tag 接口。默认项目按单商品单轮次范围运行，不增加全团队素材搜索平台。

### 7.3 鉴权图片与视频

FilePreview 使用受信任 file_url 带 Bearer fetch，检查状态与 MIME 后取 Blob，再 URL.createObjectURL。图片有放大、缩小、适应窗口；视频使用原生 controls、播放、进度、音量与全屏，必须播放实际后端视频，不用样张里的照片和三角形代替播放器。

useObjectUrls 按素材 ID／版本记录对象 URL，关闭、切换、更新文件或退出时暂停视频、解除 src、revokeObjectURL；失败请求不给空白“成功”状态。新对象创建后若 epoch 已过期立即释放。模板下载完成后也释放临时 URL。

当前短演示视频可完整下载为 Blob，在本地对象 URL 上播放和拖动；该方式不自动向服务端发带 Bearer 的 Range 请求。后端按 P4 保留 Range 支持，接口测试分别验证范围读取；不把仅能看到封面算作浏览器播放通过。若将来素材规模超出本范围，另评估受保护的流式方案，不新增到当前开发闭环。

### 7.4 图表与编辑资源的生命周期

ChartView 等容器有非零高度后再初始化；使用 ResizeObserver resize，标签显示后重新 resize，卸载 dispose 并移除 observer。更新用同一 ECharts 实例，图上缺数据为缺口；不能反复初始化导致重复监听或泄漏。[ECharts 容器说明](https://echarts.apache.org/handbook/en/concepts/chart-size/)

Quill、文件播放器、浏览器事件、请求 controller 和轮询定时器均随拥有它们的组件清理；不把整个工作台放进 KeepAlive 后继续后台轮询。切回页面以 GET 恢复，用户已保存记录保持。

完成证据：图片与可播放视频、fail_once 成功、持续失败终态、超时、排队/运行取消、迟到结果隔离、人工新任务、归档及原引用；网络读取失败不变任务状态。

## 8. F6：运营建议、主管审批与实验

### 8.1 选择范围及录入

店铺只能从本商品上架记录选择；引用本轮已确认 diagnosis_content_id/creative_content_id、可用未归档素材 material_ids。不同店铺可引用同一商品满足归属的素材，不能改 material.product_id 实现共享。

建议生成 POST /rounds/{id}/ad-proposals/generate，传 shop_id、内容 ID、material_ids、date_from/date_to、targets、instructions。targets 中 CTR／转化率／跳失率由界面百分比转换为小数，ROI 为倍数。

编辑表单完整覆盖 strategy 的 target_audience/audience_packages/bid/budget/description，A/B groups 的 group_code/material_ids/audience/bid/budget/targets，以及周期和总体目标。分组编码不能重复，素材要合法；金额非负、起止合法。不额外添加平台预算上限、真实广告账户或扣费字段。

网络中断或重复点击不能认定批准失败就自动重发；GET 建议、审批和 experiment_id 确认结果。409 保留输入并重读版本／素材，不能直接把本地 status 改成 approved。

### 8.3 实验展示

GET /experiments/{id} 展示 approved_proposal_id、实验编码、商品、轮次、店铺、周期、groups、目标快照、模拟备注及 reviews 索引。批准后的实验目标和素材采用快照，当前建议、库存或素材更新不能改写它。

实验组选择来自该实验，不能仅用字符串 A/B 跨实验混用。只有已批准实验提供经营写入口；运营确认文字、待审建议或单纯填写执行备注都不开放数据回填。

完成证据：两个账号依次确认、提交、驳回、新版重提与批准；运营审批 403；归档待审阻止审批；批准后编辑重审，旧实验保持。

## 9. F7：导入、经营数据、复盘与下一轮

### 9.1 四种模板与浏览器初检

类型使用 products/inventory/competitors/metrics。GET /imports/templates/{type}?format=xlsx/csv 走鉴权文件下载，两角色可用。规范表头及必填字段直接复用后端需求 §8.1，商品导入不自动建立 SKU、店铺映射；库存导入要求映射已存在。

Element Plus Upload 使用手动上传 auto-upload=false：选文件→读 ArrayBuffer→SheetJS 解析→选工作表→字段映射→浏览器初检。只支持契约的 xlsx 和 UTF-8 CSV，文件选择 accept 只是辅助，初检仍检查类型、解析、表头、空数据与工作表。[Element Plus 上传组件](https://element-plus.org/en-US/component/upload.html)、[SheetJS Vue 使用说明](https://docs.sheetjs.com/docs/demos/frontend/vue/)

保留原 File、原表头和原行号（表头第 1 行，数据第 2 行起）。选工作表先决定原表列，再映射；Excel 日期按单元格值解析成业务日期，CSV 读原字符串；不以自动类型推断丢失编码前导零或将空详情变 0。

原表头→规范字段为映射方向；一列不能同时映射两个目标，必填目标必须有对应列，同一目标不得冲突映射。模板表头一致时可预填，显示客户端格式错误但保留所有原行交后端校验；有错误行不意味着禁止其它有效行导入。

不同文件、sheet、类型、映射变化均使旧预览和重复选择失效。主管只可下载模板、输入已知 batchId 查看既有结果，不允许上传解析、预览或提交。未定义导入历史列表接口，样张“最近导入记录”使用本会话已知批次入口与指定批次查询；不能假装能遍历后端全部批次。

### 9.2 后端预览、重复选择与提交

1. POST /imports/preview，FormData 包含原 file、import_type、JSON.stringify(field_mapping)、所选 sheet_name；CSV 省略或按实际 multipart Schema 的空值方式提交，返回 sheet_name=null，不发送字面字符串 "null"。
2. 201 批次返回后保存 batchId 到路由 query；GET /imports/{id}?page/page_size 用于恢复与完整明细。预览 summary 的 valid/invalid/duplicate 与提交 created/updated/skipped/failed 分开。
3. 行组件使用 row_number、normalized_data、validation_status、details、duplicate_group、existing_resource_id 展示错误及原值，不能靠表格排序后的下标定位。
4. 文件内重复组显式选保留一行（新行 keep，已有记录 update），其余 skip；也可整组 skip。库内重复为 update/skip。选择保存在按原行号索引的状态，翻页不丢失。
5. 确认前必须取得涉及重复组的完整信息，未解决组返回对应行处理；没有可提交有效行则禁用。错误行允许保留并导入有效行。
6. POST /imports/{id}/commit 只发 row_resolutions，不发浏览器改过的 normalized_data。后端重读同一文件、工作表和映射，每行业务记录／库存流水原子提交。
7. 成功显示整批新增、更新、跳过、失败及逐行结果；部分成功不写“全部导入成功”。修正错误原文件后新建批次，已 committed 批次不重提交。

请求超时／断网时不能重发 commit：GET 批次确认 committed 或 committing，显示“结果确认中”；后台进程异常遗留 committing 时展示已处理行和待核对信息，由运营修正未处理行建新批次，不能在浏览器自动续写已经提交的行。

“有效／错误／重复”预览过滤、错误 CSV 导出需要完整行集：顺序读取 rows 分页到 total，检测批次状态和总数稳定；有一页失败就提示未完成，不冒充全量。结果变化时重新读取，不能把预览数据混入最终结果。

导出 CSV 含原行号、字段、原因和 normalized_data 的相应原值，UTF-8 可带 BOM，正确引号转义；对于以 =、+、-、@、制表符等开头的危险文本使用文本防公式注入处理。错误数值同时保留可辨认原值供修正。修正以原模板重新上传，不把导出的错误说明 CSV 直接当业务模板。

日期在实验周期、计数非负整数、金额非负，详情两字段都空或都填且跳失≤访问。零值合法；不增加点击≤曝光或订单≤点击等未确认约束。选日期／组后通过已有经营列表找到对应行及 ID，再编辑；不能凭手写 group_id 跨实验提交。

统计展示依赖后端汇总，跨页／日／组不能直接平均比率。CTR/转化率/跳失率百分比两位小数，ROI 两位及“倍”；正数中点向上，4.485 显示 4.49。formatter 使用明确的 halfExpand 展示规则并对基准值测试，不以浮点金额运算计算或保存实绩。

targets 的输入百分数除以 100 转 API 小数，读取乘以 100 展示；ROI 不缩放。金额一直用十进制文本；操作时间按 Asia/Shanghai 显示，业务 YYYY-MM-DD 不先转 UTC 再切日期。

zero_denominator 显示“不可计算”，missing_data 显示“缺少数据”；null 与 0 区分。部分详情数据只展示 detail_available_scope 子范围，完整范围跳失率仍 null。图表缺失日期保持断点，并显示缺失日期／组、缺详情行数。事实不能由无详情数据的低转化推成“跳失率已偏高”。

目标／实际表与四指标对比图使用同一实验和期间；百分比差异写“百分点”，ROI 写“倍”，目标方向 CTR/转化率/ROI≥、跳失率≤。达标判断使用未舍入值，tooltip 注明范围、单位和数据完整性。

A/B 组汇总用已有 GET metrics 的 group_code 分别查询，沿用同一日期范围和上下文，再与未指定组的整体汇总对照；不假定响应已有未定义的 group_comparison 字段。走势图取齐当前范围每日记录：单组可直接使用各行原始值和服务端派生值；全部组的每日比率用同 GET 按单日日期范围读取服务端汇总，限制同时读取为 2，加载或失败可见，切换停止旧读取。不用当前一页拼完整趋势，也不新增趋势 API。

numbers.js 的差值展示按传入数值的十进制文本做减法和最终舍入，再显示百分比／倍数；不能先做二进制浮点减法再假定 halfExpand 修复边界。例如 4.485−5 的精确值为 −0.515，显示 −0.52。此适配只用于展示后端已给的指标及目标，不计算或写入业务事实；无需引入金额计算平台。

| --- | --- |

### 9.6 下一轮：先建轮次、再生成诊断

确认报告且至少选一有效行动，POST /reviews/{id}/next-round，输入 expected_version/action_ids。按钮核对来源版本及行动，不自动改售价、备货或广告。

- 201 round/diagnosis：切换新 round.id，展示 source_report_id/selected_actions，诊断仍 draft，须编辑确认。
- 502/504：服务端可能已保存新轮次。解析 details 的 field=round_id 说明，并 GET /products/{id}/rounds，从来源报告与行动找到该轮。进入该轮显式 POST /rounds/{id}/diagnoses/generate 重试，不再 next-round。
- 409 同来源行动已创建：读提示及轮次索引，选择已建立轮次，避免重复建轮。
- 网络结果不明：先读索引核对同来源报告／行动；客户端不能可靠确认是否仍在处理时保留“待核对”，不自动重放写操作。

第 1 轮全部记录仍可查看；第 2 轮不复用旧 round_id。图 19 的“诊断生成中”是 next-round 的等待反馈，不新增文字诊断任务 API、SSE 或状态轮询协议。

完成证据：四模板、工作表选择、反向映射拒绝、原行号及分页重复选择、部分成功及完整错误 CSV；手工实绩、全范围汇总、自动五部分报告、Markdown保存刷新、模型失败恢复和第二轮来源记录。

## 10. F8：联调、业务验收与证据

### 10.1 与后端共同推进的方式

每个阶段按“后端契约和权限可用→前端正常操作→前端异常反馈→刷新重新读取→后端持久化核对”完成。前端按 F0—F8 的依赖开展；后端 P2 之前可以完成布局和会话，P3/P4/P5/P6 分别开放真实联调。不把同一业务拆成多套状态或另做一套演示后端。

联调使用后端流程 P7 的两个账号、正式种子和演示情景。测试夹具仅用于断网、延迟、恶意 Markdown 和组件测试；最终闭环必须使用真实 API、数据库、worker 和可用文字模型。任务成功、失败、超时和取消虽为可控教学情景，仍需真实调度及持久化；这与文字 AI 调用失败时不可静默使用样例是两个不同边界。

## 13. 构建与发布流程

### 13.1 开发和构建命令

以下命令只有 F0 工程及 scripts 实际创建并锁定依赖后才可运行。本次未创建 package.json、安装依赖或执行这些应用命令。工作目录为 frontend，Shell 为 PowerShell：

~~~powershell
Set-Location -LiteralPath 'D:\shangguigu\shopkeeper\frontend'
npm ci
npm run lint
npm run test
npm run build
npm run test:e2e
~~~

开发用 npm run dev，产物本地检查用 npm run preview。E2E 的 baseURL／webServer 与测试服务对应；真实服务先按后端流程启动 MySQL→迁移与种子→FastAPI→worker，再运行前端。首次安装所选 Playwright 浏览器时按该锁定版本说明操作，并实际记录安装及运行结果；不把缺浏览器导致跳过当通过。

产物为 dist；preview 仅本地检查，不是生产服务。[Vite 构建](https://vite.dev/guide/build)、[静态部署说明](https://vite.dev/guide/static-deploy)

### 13.2 最小生产部署约定

采用同站点静态文件＋/api 反向代理的简单部署，不增加前端 Node 常驻应用服务。部署使用项目实际选定的现有静态服务器；当前未指定主机和服务器，不预编造已运行配置。

| 部署项 | 必须落实与实际验证 |
| --- | --- |
| 路径 | 默认站点根路径；若部署子目录，构建 VITE_APP_BASE、Router history base、资源路径一致。直接刷新登录、大盘、商品工作台及导入 batchId 可恢复。 |
| 路由回退 | 仅前端页面路由回退 index.html；/api、受保护文件及缺失静态资源保留真实状态，不能将 401/404 返回为 HTML 200。 |
| API 转发 | /api 原样转发到 FastAPI，保留 Authorization；开发 proxy 不会进入 dist。生产请求不得指向用户机器的 localhost。 |
| 超时与大小 | 代理读超时高于实际文字模型请求及事务处理上限，上传限制与后端文件限制一致；给用户明确超时／文件超限反馈，不自动重放。 |
| 缓存 | 带哈希静态资源可长期缓存；index.html 每次校验更新；身份、私有数据及受保护文件避免共享缓存和 service worker 离线副本。 |
| 凭据 | 公网／共享部署使用 HTTPS；本机课堂环境按现有规则运行。VITE 变量只有公开地址／路径，构建产物和 source map 不含服务密钥、固定 JWT 或真实账号密码。 |
| 服务就绪 | 前端可达仅证明静态服务，分别检查 me、数据库保存、worker 领取和真实模型调用；没有新健康检查 API 时用已有权限接口及后端运行证据。 |
| 错误可定位 | 页面有业务错误、字段错误、资源 ID 和最后更新时间；客户端不打印完整密码、密钥、token 或包含敏感输入的响应，按后端错误结构记录脱敏信息。 |
| 发布与回退 | 记录构建日期／版本、锁定 Node/npm/依赖及匹配后端版本，保留上一 dist；新版本检查通过后切换静态产物。回退需匹配后端契约，数据库回退沿用后端迁移方案，不能靠替换 dist 回滚数据。 |

发布前检查三种访问：站点首页、直接打开已有商品轮次工作台、带 batchId 的导入结果；再检两角色登录、鉴权文件、404、模型失败、队列任务及刷新恢复。成功构建不能代替这些部署验证。
