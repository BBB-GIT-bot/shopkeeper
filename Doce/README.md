# 电商运营助手

电商运营助手是一个面向教学演示的单品运营工作台。项目围绕“商品建档与竞品录入 → 智能诊断 → 创意方案 → 异步素材制作与审核 → 投放建议与主管审批 → 经营数据回填 → 闭环复盘 → 下一轮诊断”建立完整业务闭环。

> **当前状态（2026-09-28，本轮连续开发）**：已补齐主流程后端与工作台代码、独立 worker、可播放教学视频、Excel/CSV 实际导入、审批与复盘、示例数据和模板。后端最终 41 项完整回归已通过，真实 MySQL 6 项集成验证通过，前端构建及依赖审计通过。**尚未全量验收**：真实文字模型服务未配置/实测，浏览器逐项操作与 A1–A8 人工验收待完成。示例文字明确选择教学模式，未配置模型时真实生成返回 503，不静默冒充真实结果。下方旧轮次记录保留为历史，本轮结果见末尾。

## 项目目标

- 为运营人员提供商品、店铺、SKU、竞品、诊断、创意、素材、投放实验和复盘的一体化工作台。
- 为主管/管理员提供投放审批、模型服务配置、任务队列和模拟店铺授权管理。
- 以真实文字模型生成诊断、创意、投放建议和复盘内容；图片、视频使用真实异步任务流程生成并明确标注为“演示素材”。
- 记录版本、快照、库存流水、任务尝试、审批、导入结果和经营数据，保证历史记录可追溯。

## 教学边界

本项目用于课堂演示，不连接外部广告账户、不自动创建广告计划、不触发扣费，也不抓取真实竞品网站。店铺授权是平台接入占位，保存平台、店铺标识和脱敏授权状态，禁止保存明文密码或 Cookie。经营投放通过人工执行备注模拟。

文字模型密钥只在后端使用，配置页面仅展示脱敏值。示例经营数据为合成教学数据，示例图片和视频为演示素材，必须与真实模型调用结果区分标识。

## 角色

| 角色 | 主要权限 |
| --- | --- |
| 运营人员（operator） | 维护商品、店铺业务资料、SKU 与库存；录入竞品；生成/编辑/确认内容；创建任务并审核素材；提交投放建议；录入经营数据；编辑和确认复盘。 |
| 运营主管/管理员（manager） | 查看业务数据；审批或驳回全部投放建议；维护文字模型、多模态服务、队列参数和模拟授权。不能替代运营编辑业务内容。 |

运营“确认内容”不等于投放批准。建议的新版本必须重新确认并重新审批；已批准版本归档后，原实验和历史数据仍可读取。

## 技术方案

目标实现采用：

- 后端：Python、FastAPI、同步 SQLAlchemy/PyMySQL、MySQL 8.0、独立 Python worker。
- 前端：Vue 3、JavaScript、Vite、Vue Router、Element Plus；图表使用 ECharts，富文本使用 Quill，复盘支持 Markdown 预览。
- 队列：数据库持久化任务和尝试，worker 负责领取、心跳、超时回收、重试、取消及结果回写。
- 模型：后端通过可配置的兼容 HTTP 服务调用真实文字模型；失败、超时和结构不合格时保留已有版本并允许重试。
- 文件：图片/视频按任务尝试和素材版本隔离保存，只有成功且审核通过的版本进入可用素材选择列表。

## 业务与数据规则

- 同款商品只有一份统一商品档案，可以关联多个店铺。上架记录、平台 SKU 映射、售价、库存和经营数据按店铺分别保存，库存不跨店铺共享。
- 诊断、创意、任务、素材、投放建议、实验和复盘均绑定商品与运营轮次；历史下游引用使用版本快照，不随当前资料变化。
- 诊断必须包含目标客群、价格带分析、卖点矩阵、转化卡点和优化方向。
- 创意至少包含 3 组差异化主图方向和 3 套完整视频脚本；主图需要构图、文案、卖点和视觉建议，脚本需要 3 秒钩子、分镜、口播和促单话术。
- 任务状态为 `pending`、`running`、`succeeded`、`failed`、`timeout`、`cancelled`。默认轮询 2 秒、并发 2、执行超时 60 秒、自动重试 2 次；取消后的迟到结果不得改变终态或创建可用素材。
- 导入后端校验是最终依据。有效、错误、重复行分别保留结果；库存导入与流水在同一行事务中完成，经营数据五维唯一，重复导入不能累加。
- 指标先汇总原始值再计算：CTR、转化率、ROI、详情页跳失率和在售动销率。分母为零显示“不可计算”，缺失详情页数据不得推断跳失原因。

## 页面范围

1. **运营大盘与店铺概览**：多店铺卡片、商品去重统计、动销率、走势、库存预警、检索和导入入口。
2. **商品智能运营工作台**：商品/轮次上下文；档案与诊断、创意与素材、投放与复盘三个区域；支持历史版本和资源索引恢复。
3. **批量导入与数据中心**：模板下载、Excel/CSV 上传、字段映射、客户端初检、后端预览、重复处理和逐行结果。
4. **系统与服务配置**：真实文字模型、多模态模拟模式、队列并发/超时/重试、模拟平台授权；仅主管可写。

## 接口与状态约定

后端契约包含认证、大盘、商品/库存/竞品、内容、任务/素材、投放/实验、经营/复盘、导入和配置接口。成功响应直接返回资源或分页体，不额外包裹 `data`；创建通常为 201，异步任务入队为 202，错误使用 `code/message/details`。版本型编辑使用 `expected_version`，冲突返回 409；未授权或越权分别返回 401/403。

前端必须从 `/auth/me` 获取当前角色，token 仅保存于会话存储；401 清除会话并停止轮询，403 保留登录状态并提示无权限。切换商品、轮次、店铺或实验时停止旧请求与轮询，防止旧响应覆盖新上下文；未保存表单离开前必须提示。

## 防晒衣演示基准

完整课堂场景为“夏季凉感防晒衣冷启动”：店铺 `SHOP-A`、`SHOP-B`，商品 `SUN-001`，蓝/灰与 S/M 四个 SKU，基础售价 299 元。`SHOP-A` 进行 A/B 实验，周期使用 2026-09-21 至 2026-09-27 的合成历史数据。

| 范围 | 曝光 | 点击 | 订单 | GMV | 花费 | 详情访问 | 详情跳失 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A 组七天 | 70,000 | 1,400 | 28 | 8,372 | 2,100 | 1,260 | 882 |
| B 组七天 | 70,000 | 2,100 | 35 | 10,465 | 2,100 | 1,890 | 1,512 |
